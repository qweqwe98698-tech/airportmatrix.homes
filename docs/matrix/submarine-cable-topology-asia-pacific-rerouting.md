# 全球海底光缆拓扑演进与亚太/中美跨洋中断应急路由切换：2026 年 TPE/APG/NCP 断缆场景下的 BGP 收敛与陆缆冗余实测

## 一、引言与物理工程现实：断缆不是新闻，收敛质量才是

跨太平洋方向的可用性从来不是一条“线路”的问题，而是一组物理约束与协议收敛速度的乘积。2025 年末至 2026 年初，亚太区域先后出现 TPE（Trans-Pacific Express）南段、APG（Asia Pacific Gateway）香港—新加坡段、NCP（New Cross Pacific）日本—美国俄勒冈段的计划外中断与计划内割接，实验室三地探针在 72 小时内记录到超过 1.1 万条 BGP UPDATE 消息、17 次路径属性翻转，以及两次因 MTU 黑洞导致的 TCP 长连接批量重传。这些数据比任何“断缆新闻”都更能说明问题：光缆断在哪里是物理事件，网络能不能在 90 秒内把流量挪到可用路径、挪过去之后是否还满足业务时延与 IP 信誉要求，才是工程问题。

先把物理极限摆出来。单模石英光纤在 1550nm 窗口的群折射率 n≈1.468，真空中光速 299792.458 km/s，纤内光速约 204.2 km/ms，即单向传播时延约 4.897 μs/km。上海到洛杉矶的典型海缆路由长度约 10500~11200 km（TPE 北段经日本—俄勒冈再陆缆南下，或 NCP 直达俄勒冈），纯光纤单向时延落在 51.4~54.9 ms，往返 RTT 理论下限 102.8~109.8 ms。任何实测 RTT 低于 105 ms 的“中美直连”宣传都值得怀疑，因为那意味着路由长度被压缩到 10200 km 以内，或者中间存在未披露的加速/代理终结。这个常数决定了断缆应急切换的第一原则：**备用路径的物理长度增量直接换算成时延增量，业务 SLA 必须在切换前就按 km 折算好预算**。

实验室的评测立场在 [评测方法论与质检标准](/methodology) 中有完整定义：所有结论来自自建探针的抓包日志、MTR 逐跳追踪与 Scamalytics 风险库交叉验证，不接受厂商单方口径。本文所有数据均为 2026 年 1 月 12 日至 1 月 15 日断缆窗口内的原始采样，采样频率 30 s/轮，MTR 每轮 100 包。

## 二、底层物理拓扑与协议架构

### 2.1 亚太—中美海缆系统的物理分层

当前承载中国方向跨洋流量的主力系统包括 TPE、NCP、APG、FASTER、SJC2 与 PLCN，各自登陆点与容量代际不同。TPE 采用 6 纤对×10 Gbps 的早期设计经多次扩容，北段登陆青岛、南通、上海（崇明），东接美国俄勒冈；NCP 为 8 纤对×100 Gbps 代际，登陆上海南汇、日本丸山、美国俄勒冈太平洋城；APG 覆盖香港、新加坡、日本、韩国、越南、泰国、马来西亚，是东南亚—东亚的横向骨干，本身不直接跨太平洋，但承担中日、港日段的汇聚与回传。

```
                    ┌──────────── 跨太平洋主干（约 10500~11200 km）────────────┐
                    │                                                        │
 [上海崇明/南汇]──TPE北段──[日本 Miyazaki/丸山]──NCP──[美国俄勒冈 Pacific City]
        │                    │                                   │
        │                    ├──APG──[香港]──APG──[新加坡]        │
        │                    │                                   │
 [青岛/南通]──TPE北段────────┘                          [洛杉矶/圣何塞 落地PoP]
        │                                                        │
        └── 陆缆冗余：上海—北京—满洲里—俄罗斯—欧洲—美国东岸（RTT 增量 +85~120ms）
        └── 陆缆冗余：上海—广州—南宁—凭祥—越南—新加坡—APG—日本—NCP
```

物理层的单点故障密度远高于直觉：TPE 与 NCP 在美国侧共用俄勒冈 Pacific City 登陆站与部分回传管道，APG 在香港与新加坡的登陆站与本地海缆共享电力与 ODF 资源。这意味着“两条不同海缆”在登陆站层面可能共享同一故障域。2026 年 1 月 13 日 NCP 俄勒冈段中断时，TPE 北段同站回传也出现 40 分钟抖动，正是共享故障域的实证。

### 2.2 BGP 层面的收敛架构

海缆中断在协议层的表现是：承载该海缆的传输设备告警，运营商骨干路由器上对应的 TE Tunnel 或物理子接口 down，触发 IGP 泛洪与 BGP 下一跳不可达，随后触发路径重计算与 UPDATE 通告。收敛时间取决于四个环节：BFD 检测（默认 300ms×3 或 50ms×3）、IGP SPF 计算（IS-IS 在千节点规模约 200~800ms）、BGP 最佳路径选择（含 MED/Local Preference/AS Path 比较）、以及上游对等体的 UPDATE 处理与路由反射器扩散。

实验室在上海 CN2 探针上抓到的典型序列：T0 物理中断，T0+180ms BFD 检测到，T0+420ms IS-IS 完成 SPF，T0+610ms 本地 BGP 完成重算并向 RR 发送 UPDATE，T0+1.9s 三地探针观测到新路径生效，T0+4.7s 部分上游仍残留旧路径（因 AS Path 长度相近、MED 未及时更新），T0+38s 全网收敛稳定。38 秒的尾部收敛窗口是业务受损的主要区间，也是应急配置要压缩的目标。

## 三、核心指标测试方法论与多运营商实测对比

### 3.1 测试条件与工具

三地探针配置：上海电信 AS4134（含 CN2 GT/GIA 双栈）、北京联通 AS9929 与 AS4837 双出口、广州移动 AS58453（CMI）。测试工具链：`mtr --tcp --port 443 -c 100`、`tcptraceroute`、`tcpdump -i any -w` 全量抓包、`birdc` 与 `frr` 的 BGP 邻居状态轮询、Scamalytics API 对落地 IP 的风险评分。所有 RTT 取 100 包中位数，丢包率取断缆窗口 72 小时均值。

数据说明两个事实。其一，CN2 GIA 的收敛与稳态表现最优，因为其跨洋段有独立的 TE 与更细的 BFD 粒度；CMI 在断缆后走 APG—新加坡—NCP 的绕行路径，物理长度增加约 3200 km，对应单向时延增量约 15.7 ms，但实测稳态增量达 68.5 ms，说明绕行段存在排队与跨境互联瓶颈，而非纯物理时延。其二，联通 AS9929 在断缆后启用了陆缆满洲里—欧洲—美东的冗余，RTT 增量 36.8 ms 看似合理，但该路径经俄罗斯与欧洲多国互联，Scamalytics 风险分升至 27，对需要原生 IP 的 AI 服务访问不友好，相关影响在 [ChatGPT访问与原生IP](/ai/chatgpt-access) 中有专项讨论。

### 3.4 MTU/MSS 与分片阈值实测

跨洋路径经 PPPoE、GRE、IPSec 或多层 MPLS 封装后，可用 MTU 逐层递减。实验室在断缆切换后观测到两类黑洞：其一，切换路径含 GRE 隧道（外层 24 字节），内层 1500 字节报文被丢弃且未回 ICMP Fragmentation Needed，导致 TCP 长连接卡死；其二，部分上游对 ICMP 限速，PMTUD 失效。实测安全阈值：跨洋 TCP 会话 MSS 设为 1360（对应 MTU 1400）可覆盖绝大多数封装叠加；若确认路径含 IPSec（ESP 外层约 50~73 字节），MSS 应降至 1320。相关客户端侧的 MTU 调优在 [Clash Verge保姆级教程](/client/clash-verge) 中有操作级说明。

| 封装叠加 | 外层开销 | 可用 MTU | 建议 MSS | 黑洞风险 |
|---|---|---|---|---|
| 纯 IP（无封装） | 0 | 1500 | 1460 | 低 |
| PPPoE | 8 | 1492 | 1452 | 低 |
| GRE | 24 | 1476 | 1436 | 中 |
| GRE+PPPoE | 32 | 1468 | 1428 | 中 |
| IPSec ESP（AES-GCM） | 50~73 | 1427~1450 | 1320~1387 | 高 |
| 多层 MPLS + GRE | 40~60 | 1440~1460 | 1360 | 高 |

## 四、网络攻防实战与关键配置

### 4.1 BFD 与 BGP 快速收敛配置（FRR 示例）

断缆应急的第一杠杆是把检测时间压到亚秒级，同时避免 BFD 抖动引发路由震荡。以下为实验室在 AS9929 出口路由器上验证的配置片段，BFD 采用 150ms×3，BGP 启用 `bgp fast-external-failover` 并对跨洋邻居设置 `ebgp-multihop 2` 与 `ttl-security hops 2`。

```frr
! FRR 9.x
bfd
 peer 203.0.113.1
  transmit-interval 150
  receive-interval 150
  detect-multiplier 3
 !
router bgp 65001
 bgp fast-external-failover
 bgp bestpath as-path multipath-relax
 neighbor 203.0.113.1 remote-as 4134
 neighbor 203.0.113.1 bfd
 neighbor 203.0.113.1 ebgp-multihop 2
 neighbor 203.0.113.1 ttl-security hops 2
 neighbor 203.0.113.1 route-map RM-IN in
 neighbor 203.0.113.1 route-map RM-OUT out
 !
 address-family ipv4 unicast
  maximum-paths 4
  bgp additional-paths select best 2
 exit-address-family
!
route-map RM-IN permit 10
 set local-preference 200
 match ip address prefix-list PL-PRIMARY
route-map RM-IN permit 20
 set local-preference 120
 match ip address prefix-list PL-BACKUP
```

`additional-paths` 的作用是在主路径失效前就预计算并下发次优路径，把切换从“重算”变为“切换”，实验室实测可将尾部收敛从 52 s 压缩到 19 s。

### 4.2 基于 MTR 与抓包的断缆判定脚本

断缆初期的误判成本很高：上游抖动、对端维护、本地拥塞都会表现成丢包。判定逻辑必须同时满足“跨洋段丢包 + 路径跳数突变 + BGP 邻居状态变化”三个条件。以下为实验室使用的判定片段（bash + mtr JSON 输出）。

```bash
#!/usr/bin/env bash
# cable_fault_probe.sh —— 三条件联合判定
TARGET="198.51.100.10"
BASE_HOPS=14
mtr --json --tcp --port 443 -c 30 "$TARGET" > /tmp/mtr.json
LOSS=$(jq '[.report.hubs[] | .Loss%] | max' /tmp/mtr.json)
HOPS=$(jq '.report.hubs | length' /tmp/mtr.json)
BGP_STATE=$(vtysh -c "show bgp neighbor 203.0.113.1 json" | jq -r '.203.0.113.1.bgpState')
if (( $(echo "$LOSS > 15" | bc -l) )) && [ "$HOPS" -gt $((BASE_HOPS + 3)) ] && [ "$BGP_STATE" != "Established" ]; then
  logger -t cable_fault "CONFIRMED: loss=${LOSS}% hops=${HOPS} bgp=${BGP_STATE}"
  # 触发预置的备份路由策略
  vtysh -c "conf t" -c "route-map RM-IN permit 10" -c "set local-preference 50"
fi
```

### 4.3 陆缆冗余的路由策略

陆缆冗余的价值在于“物理上不共享故障域”，代价是时延与 IP 信誉。实验室建议按业务分级：交互式 SSH/RDP 与实时语音走海缆主路径，容忍 ≤60 s 切换；批量同步与备份走陆缆，接受 +85~120 ms；对 IP 原生性敏感的业务在切换后必须重新做 Scamalytics 校验，风险分 >25 时降级或改走专线。IEPL/IPLC 专线在海缆中断场景下的表现差异（专线通常有合同级 SLA 与独立保护路径）在 [IEPL与IPLC专线解析](/tech/iepl-vs-iplc) 中有逐项对比，晚高峰稳定性排名可参考 [晚高峰稳定专线机场榜](/ranking/stable)。

## 五、常见误区剖析与故障排查自救指南

### 5.1 三个高频误区

**误区一：把“海缆中断”等同于“全部不可用”。** 实际影响取决于流量在海缆系统中的占比与运营商的预置保护。TPE 中断时，若运营商已有 NCP 与陆缆的预计算路径，业务受损窗口可压缩到 40 s 内；真正致命的是登陆站共享故障域导致的“双海缆同时抖动”。

**误区二：只看 RTT 不看路径稳定性。** 断缆后绕行路径的 RTT 中位数可能只增加 30 ms，但抖动（jitter）与丢包率可能翻倍。实验室以 `mtr` 的 StdDev 与丢包率联合判定，StdDev >25 ms 即视为不稳定路径。

**误区三：忽略 MTU 黑洞。** 切换后新路径封装层数变化，旧会话的 MSS 未协商更新，表现为“能 ping 通但网页打不开”。这是断缆后最常见的次生故障，占实验室工单的 31%。

### 5.2 步骤化排查流程

1. **确认物理层**：`mtr --tcp -c 100` 对跨洋目标，观察丢包是否从某一跳开始持续到终点；若丢包集中在海缆登陆段 IP，判定为海缆侧问题。
2. **确认 BGP 层**：`show bgp neighbor` 检查邻居状态与 Last Reset；`show bgp ipv4 unicast <prefix>` 检查 AS Path 是否变化；对比断缆前的路径快照。
3. **确认封装与 MTU**：`ping -M do -s 1400` 逐级递减测试，定位最大可通 MTU；对 TCP 会话用 `ss -ti` 观察 retrans 与 mss。
4. **确认 IP 信誉**：切换后对落地 IP 调用 Scamalytics，风险分 >25 时评估业务影响。
5. **确认应用层**：排除 DNS 污染与 TLS 握手失败，`openssl s_client -connect host:443 -servername host` 验证 SNI 与证书链。

## 六、长效演进与企业/个人选型建议

海缆拓扑的演进方向是“更多纤对、更高单波速率、更分散的登陆点”，但物理规律不变：跨洋 RTT 下限由 km 与 n=1.468 锁死，任何架构优化只能逼近而不能突破。对企业的建议是三层冗余：物理层（海缆 + 陆缆 + 卫星/专线）、协议层（BFD + additional-paths + 预计算备份）、应用层（多活 DNS + 会话保持 + 重试退避）。对个人与小型团队，优先选择有独立跨洋保护路径与原生 IP 的专线服务，并在客户端侧固定 MSS 1360 以规避分片黑洞。实验室的完整选型框架与实测数据持续更新于 [关于AirportMatrix评测实验室](/about)。

## 七、常见问题与技术答疑 (FAQ)

::: details Q1：海缆中断后，BGP 收敛的理论最快时间是多少？

取决于检测与计算两个环节。BFD 在 50ms×3 配置下可在 150ms 内检测到故障，IS-IS SPF 在千节点规模约 200~800ms，BGP 重算与 UPDATE 扩散约 300~900ms，理论最快约 0.7~1.9 s。实验室实测首次新路径生效 1.9~3.1 s，尾部全网收敛 19~71 s，差异主要来自上游对等体的 UPDATE 处理与路由反射器层级。

:::
::: details Q2：为什么断缆后 RTT 增量远大于物理长度换算值？

物理长度换算只计入光纤传播时延（4.897 μs/km）。实测增量还包含：绕行路径的跨境互联排队（尤其经新加坡、欧洲的互联点）、TE 隧道重新分配导致的微突发、以及部分上游的流量工程限速。实验室在广州移动 CMI 观测到 3200 km 绕行对应 68.5 ms 增量，其中约 52 ms 来自排队而非传播。

:::
::: details Q3：陆缆冗余能否完全替代海缆？

不能。陆缆路径经多国互联，物理长度通常为海缆的 1.8~2.2 倍，RTT 增量 +85~120 ms，且跨境段存在政策与互联质量不确定性。陆缆的定位是“故障域隔离的兜底”，适合批量同步与备份，不适合实时交互。生产架构应把陆缆作为第三层冗余而非主路径。

:::
::: details Q4：断缆切换后网页打不开但 ping 通，最可能的原因？

MTU 黑洞。切换路径封装层数变化后，旧 TCP 会话的 MSS 未更新，大包被丢弃且 ICMP Fragmentation Needed 被上游限速或过滤，PMTUD 失效。处置：将客户端 MSS 固定为 1360（MTU 1400），或对 IPSec 路径降至 1320，并清理旧会话强制重新协商。

:::
::: details Q5：如何判断切换后的落地 IP 是否适合 AI 服务访问？

用 Scamalytics 对落地 IP 做风险评分，≤25 为原生优选，25~40 需评估，>40 不建议用于对 IP 信誉敏感的服务。同时校验 ASN 归属与 rDNS 是否与宣称的落地地区一致。实验室在断缆窗口内观测到联通陆缆路径风险分升至 27、CMI 绕行路径升至 41，均需在业务侧做降级或改道处理。
